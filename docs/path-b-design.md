# Path B — Guided Write (不确定的作者)
## 产品路径设计 v0.1

> 从设计对话整理。对应 METHODOLOGY.md §2（三模块架构）的完整实现。
> Path A（已构思好，直接填写）另行记录。

---

## 两条路径的分叉点

进入 `/write` 时，一个问题决定路径：

> **你已经知道你在写什么了吗？**
> - 知道，帮我写出来 → Path A（模板编辑器）
> - 还不确定 → Path B（本文档）

Path B 的用户状态：有素材（人物、事件、地点、经历、采访记录），但不知道中心在哪、结构是什么、从哪里开口。

---

## 完整路径

```
阶段 0   项目启动
   ↓
阶段 1   situate.map（找中心）
   ↓
阶段 2   situate.act（定形状）
   2a  时间形状
   2b  场所形状
   2c  人物图谱 + 人物档案
   2d  人物弧光
   ↓
阶段 3   situate.at（写场景）[循环]
```

中心卡片（阶段 1 生成）全程可见。作品蓝图（阶段 2 生成）全程可见。

## 阶段 0：项目启动

### 用户输入

**① 驱动类型**（§4）

```
你为什么要写这个？
○ 我要给某种读者讲某件事
○ 有个东西缠住我，必须写出来
○ 现在不知道
```

驱动类型决定后续的初心记录方式。缠绕型（缠住我）只需一行字；目的型需要填：给谁 / 为什么 / 读者获得什么。不知道的可以跳过，阶段 1 完成后系统会再问一次。

**② 真实性声明**（§18，项目级别，一次性）

```
○ 完全基于真实经历和人物
○ 完全虚构
○ 介于两者之间
+ 是否涉及真实可识别的人？（是 / 否）
+ 地点是否是真实的公共场所？（是 / 否）
```

这两个声明在之后每个阶段的反馈里都会用到（§6 的 ◎ 服务意图 / §18 的编辑门槛预览）。在动笔前问，不在提交时才问。

## 阶段 1：situate.map（找中心）

### 用户输入

**素材描述**：你手里有什么？流水账就行。人物、事件、地点、读过的文件、做过的采访。不用写得好，目的是把材料倒出来。

### 系统生成

**5–6 个角度问题**：从 8 个普遍角度（§7）里挑最有密度的，用素材里真实的名字和细节实例化。（已实现，`src/lib/map/angles.ts`）

每个问题附 2–3 个引子，故意往不同方向走，帮写作者开口。

### 用户输入

**回答这些问题**：随便写，一两句也行。引子只是入口，不用跟着走。

### 系统生成

**归纳结果**（`src/lib/map/synthesis.ts`）：
- 从每条回答提取 1–3 个关键短语（尽量用作者原话）
- 找出语义上跨回答重复的词
- 走三个分支之一：
  - `convergent`：短语收敛到同一样东西
  - `higher_abstraction`：短语散落在不同人/地，但共享同一系统/场所
  - `divergent`：暂时不收敛

### 用户输入

**命名中心**：系统问"这些描述在指向同一样东西。它是？"，写作者填。

### 系统生成：中心卡片

全程 pin 在所有后续阶段顶部（§12 Invariant 8）。

```
中心：[名字]
你说过的词：[从写作者回答里提取的关键短语，原话，不改]
核心问题：[这篇文章真正在问什么，一句话，用写作者自己说过的词]
最难的地方：[具体是什么难 + 这意味着动笔时要怎么做]
什么不是中心：[素材里出现但没有被中心吸引的人/地——可以放下]
```

这张卡片是写作者坐下动笔之前需要知道的全部。不是 AI 的总结，是写作者自己说过的话被整理后还给他。

## 阶段 2：situate.act（定形状）

### 2a. 时间形状

**用户输入：**
```
这个作品跨越多长时间？
○ 一个时刻 / 一天 / 一个季节内
○ 几年
○ 几十年以上
○ 不知道

几幕结构？
○ 一幕（所有事发生在同一时空）
○ 多幕
○ 不知道
```

**系统生成：承诺确认**

告知这个选择的结构后果，不推荐、不评价：

> 一幕·一天：所有重量由细节和感知密度承担，没有时间轴可以依赖。场景的选择决定一切。

### 2b. 场所形状

**用户输入：**
```
○ 一个坐标——全部发生在同一个地方
○ 几个坐标——不同场景在不同地方
○ 一条路线——人在移动
○ 不知道
```

**系统生成：坐标槽**

写作者声明了几个坐标，就提供几个槽让他命名。不填内容，只提供结构位置。

### 2c. 人物图谱 + 人物档案

**用户输入：** 除了中心，还有哪些人出现在这个作品里？列出名字。

**系统生成：功能分类框架**

```
围绕中心，作品里通常有几种功能角色：
· 见证者——看得最清楚的那个
· 对照者——体现中心所不是的那个
· 挑战者——质疑中心处境或选择的那个
· 承载者——日常存在本身就携带这个时代/世界的那个

你列出的人里，哪些可能对应哪种功能？
（可以空着，可以一个人对应多个，可以都不对应。）
```

**用户输入：** 把自己的人物对号入座（可选）

**系统生成：人物关系摘要**

把写作者填进去的东西反射回来，用他自己的词。不发明内容，只整理呈现。

---

### 人物档案（可持续丰富，不限于作品中出现的内容）

对于每个人物（包括中心），写作者可以开一个档案，写入这个人的任何信息——**不只是在作品中出现的几个时间点，而是他们知道的全部**：

```
[人物名字]
───────────────────────────────
生平 / 背景
  在作品发生的时间之前，这个人经历了什么？
  （自由填写，可以很长，也可以只有几句话）

性格 / 行为方式
  有没有某种反复出现的模式、习惯、或让你印象深刻的细节？

作者和这个人的关系
  你是怎么认识这个人的？你了解他多少？
  有没有你知道但不打算写进去的事情？

这个人在作品里承担什么
  （对应功能角色，可从图谱里拉取）

你觉得最难写准确的是什么
  （对应中心卡片里的"最难的地方"，但人物级别的版本）
```

这些档案：
- 随时可以补充，不是一次性填完的
- 不要求填满——有什么写什么
- 会作为上下文传入场景反馈（AI 只读写作者已声明的内容，不根据写作行为反推——§3 Declaration vs behavior）
- 是 Story Bible（Milestone B）的前身，之后会和 Bible 的 `entities` 表连接

场所档案同理：每个坐标可以开一个档案，写入写作者对这个地方知道的一切，不只是作品里出现的场景。

---

### 2d. 人物弧光

**用户输入**（针对中心 + 有实质内容的配角）：

```
在这个作品的开头，[人物] 是什么状态？
在结尾，是什么状态？
（"没有变化"也是一个合法答案——不变本身可以是弧光）
```

**系统生成：弧光结构说明**

告知这个选择的结构含义，不评价好坏：

> 你说的朱阿姨：开头不确定，结尾还是不确定——状态没有解决。
> 这是一种完整的弧光形状。作品的力量可以来自拒绝解决。

---

## 阶段 3：situate.at（写场景）[循环]

每个场景走一遍。中心卡片 + 作品蓝图始终可见。

### 用户输入：选择这个场景

用一句话描述要写哪个时刻。不用写好，占位符就行。

### 系统生成：场景定位

把这个场景在作品结构里的位置标出来（第几幕、第几个场景、当前进度）。

### 用户输入：两个具体化问题

**① 谁在场，在哪里**（一句话，逼具体化）

**② 你脑子里，这个场景第一个进来的是什么**
画面、声音、气味、还是一句话？这个问题的答案通常就是第一句话。

### → 写作者落笔

### 系统生成：反馈（写完后触发，不是实时的）

```
✓ 在场的：你写出来的东西
✗ 缺失的：按这个场景应该做到的，哪里还不在
◎ 服务意图：这个场景对中心卡片里的核心问题贡献了什么
✦ 服务结构：这个场景在作品时间结构里起什么作用
✨ 场景一致性：和之前写的场景在人物/时间/地点上有没有矛盾
✧ 服务场所：地点在这个场景里是在承载内容，还是只是背景
```

后四项（◎ ✦ ✨ ✧）只在有上下文时出现（中心卡片已生成、作品蓝图已生成、有之前的场景）。

## 系统在整条路径里生成什么

| 阶段 | 系统生成 | 类型 |
|---|---|---|
| 1 | 5–6 个角度问题 | 问题（用写作者素材实例化） |
| 1 | 归纳结果（分支 + 短语） | 结构诊断 |
| 1 | 中心卡片 | 写作者自己的词，整理后反射回来 |
| 2a | 承诺确认 | 结构后果说明 |
| 2b | 坐标槽 | 结构框架 |
| 2c | 功能分类框架 | 类别脚手架（写作者填具体内容） |
| 2c | 人物关系摘要 | 写作者内容的整理反射 |
| 2d | 弧光结构说明 | 结构后果说明 |
| 3  | 场景定位 | 结构位置 |
| 3  | 场景反馈（8 类） | 结构观察 |

**系统在整条路径里从不生成文学内容。** 人名、事件、场景细节、句子——全部由写作者提供。AI 提供类别、框架、结构后果、以及把写作者自己说过的话整理后还给他。

## 与 Path A 的互通

Path B 走完阶段 1–2，应该能直接进入 Path A 的模板编辑器，带着中心卡片和作品蓝图继续写。

Path A 写到一半卡住，应该能跳回 map 阶段重新找中心，不丢失已写的内容。

两条路终点相同：可提交的作品草稿。
